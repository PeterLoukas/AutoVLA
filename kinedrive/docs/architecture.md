# KineDrive: Kinematic-Aware End-to-End VLM for Autonomous Driving

## Architecture Overview

KineDrive is a novel end-to-end VLM-based autonomous driving system that introduces **4D kinematic waypoint prediction** — the first E2E model to predict speed as a first-class output alongside position and heading.

### Key Contributions

| # | Contribution | Prior Art Gap |
|---|-------------|---------------|
| 1 | **4D Kinematic Waypoints (x,y,θ,v)** | All 5 SOTA models (AutoVLA, UniDriveVLA, ReCogDrive, MindDriver, SpaceDrive) encode speed implicitly through positional spacing |
| 2 | **Kinematic Flow Matching (KFM)** | Combines UniDriveVLA flow matching with ReCogDrive's DiT in 4D space |
| 3 | **Temporal 3D Spatial PE** | SpaceDrive's 3D PE applied only to current frame; KineDrive extends to all T temporal frames with temporal offset embedding |
| 4 | **Kinematic Consistency Loss** | Novel soft penalty on implausible speed transitions (|Δv/Δt| > 5 m/s²) |
| 5 | **K-GRPO with PDM-V Reward** | Extends DiffGRPO to 4D space with Speed Profile Score in the reward |

## Architecture Components

### 1. Base Backbone: Qwen2.5-VL-3B-Instruct

- **VLM**: Qwen2.5-VL-3B (28 layers, hidden_size=2048, 16 attention heads)
- **LoRA**: rank=64, alpha=128 on all attention + FFN projection matrices
- **Vision Tower**: Frozen (following SpaceDrive, MindDriver)
- **Input**: 6 cameras × 4 temporal frames at 2Hz = 24 images
  - Each image: 640×480 → ~560 visual tokens after Qwen stride-14 merging
  - Total visual tokens: ~13,440 per sample
- **Output**: Hidden states from final layer (B, S, 2048)

### 2. Temporal 3D Spatial Positional Encoding (T3D-SPE)

Extends SpaceDrive's Universal 3D PE with temporal awareness.

**Mathematical formulation:**

For a visual token at pixel (u, v) in camera c at temporal frame f:
1. Estimate depth: d = MiDaS(I_c) or geometric fallback
2. Unproject to LiDAR frame: P_3D = K_c^{-1} · [u·d, v·d, d] via lidar2img^{-1}
3. Compute per-axis sine-cosine PE:
   ```
   φ_axis(coord) = [sin(coord/freq^(2i/dim)), cos(coord/freq^(2i/dim))]_{i=0..dim/6}
   freq = 10000, dim = 2048
   ```
4. Total PE: φ(P_3D) = concat[φ_x, φ_y, φ_z][:dim] ∈ ℝ^2048
5. Temporal offset: T_f = TemporalEmbed(f) ∈ ℝ^2048
6. Injection: token ← token + α_PE × (φ(P_3D) + T_f)
   - α_PE is a learnable scalar (initialized to 0.1)

**Key difference from SpaceDrive**: SpaceDrive computes 3D PE only for the current frame (1 timestamp). KineDrive computes separate 3D PE for each of the 4 temporal frames, with a learned temporal offset embedding to distinguish "when" tokens were captured.

### 3. Kinematic Flow Matching Action Head (KFM-Head)

A 12-layer DiT that denoises 4D kinematic trajectories conditioned on VLM features.

**Action space:**
- 8 waypoints at 0.5s intervals = 4.0s horizon
- Per waypoint: (x, y, θ, v) = (lateral m, forward m, heading rad, speed m/s)
- Normalization to [-1, 1] using physical bounds:
  - x: [-10, 10] m  (lateral: ±10m covers lane changes)
  - y: [-1, 60] m   (forward: 0-60m at 60km/h over 4s)
  - θ: [-π/2, π/2] rad
  - v: [0, 30] m/s  (0-108 km/h)

**DiT architecture:**
```
12 blocks (interleaved):
  Even (0,2,4,6,8,10): Self-attention + AdaLN + SwiGLU FFN
  Odd  (1,3,5,7,9,11): Cross-attention on VLM hidden states + AdaLN + SwiGLU FFN

Each block:
  - AdaLN conditioned on: timestep_emb(t) + ego_status_emb(9→512)
  - Self-attention: 8 heads × 64 head_dim, QK-RMSNorm
  - Cross-attention: Q from action tokens, K/V from VLM hidden states (cross blocks)
  - FFN: SwiGLU with hidden_dim=512

Input to DiT:
  [hist_traj_emb | ctx_mean | action_emb] → fusion_proj → 512-dim

Output:
  Final norm → Linear(512→4) → predicted velocity field v(x_t, t)
```

**Flow matching:**
- Training: x_t = (1-t)·x_0 + t·ε, target u_t = ε - x_0, t ~ Beta(1.5, 1.0)
- Inference: 10-step Euler integration from x_1=ε to x_0
- Loss: MSE(v_pred, u_t) + 0.1 × kinematic_consistency

### 4. Kinematic Consistency Loss (Novel)

```
L_kin = Σ_t max(0, |v_{t+1} - v_t|/Δt - a_max)²  +  Σ_t max(0, -v_t)²  +  (v_0 - v_curr)²

where:
  a_max = 5.0 m/s²  (maximum comfortable acceleration)
  Δt = 0.5s
  v_curr = current ego speed (from CAN bus)
```

This penalizes:
1. Speed transitions that require acceleration > 5 m/s² (jerk constraint)
2. Negative speeds (vehicle cannot reverse in planning)
3. Speed discontinuity at the boundary (t=0 predicted speed ≠ current speed)

### 5. Chain-of-Thought Reasoning

Structured 5-part CoT generated by Qwen2.5-VL-3B:

```
<think>
[Scene Analysis]: Weather/road/signals/drivable area
[Velocity Context]: current_speed=X m/s, [speed profile description]
[Risk Assessment]: Top-3 agents with position/velocity/state
[Speed Profile]: planned speed change (accelerate/maintain/decelerate to Y m/s)
[Action Decision]: (direction, speed_change)
</think>
<answer>
[(x1,y1,θ1,v1), ..., (x8,y8,θ8,v8)]
</answer>
```

The [Velocity Context] and [Speed Profile] sections are novel — no prior work explicitly reasons about speed profiles in the CoT. CoT annotations are generated offline using Qwen2.5-VL-72B (following AutoVLA) enhanced with CAN bus speed data.

## Training Pipeline (3 Stages)

### Stage 1: Supervised Fine-Tuning (SFT)
- **Duration**: 5 epochs, 8×A100 (40GB)
- **Data**: nuScenes + nuPlan (with 72B teacher annotations)
- **Loss**: L_SFT = 10 × L_VLM (CoT samples) + 1 × L_VLM (non-CoT)
- **Output format**: Text: [(x,y,θ,v), ...] — trains language modeling on 4D format
- **LoRA only** (VLM backbone via LoRA, vision tower frozen)

### Stage 2: Imitation Learning — Flow Matching (IL)
- **Duration**: 100 epochs, 8×A100
- **Frozen**: VLM backbone (only action_head + spatial_pe trained)
- **Loss**: L_IL = L_flow + 0.1 × L_kin
- **Speed supervision**: from CAN bus `vehicle_speed` (km/h → m/s) for future frames
  - When CAN bus unavailable: derived from ||Δpos||/Δt

### Stage 3: K-GRPO Reinforcement Learning
- **Duration**: 10 epochs, 8×A100
- **Frozen**: VLM backbone (only action_head trained)
- **Reward**: R = PDM_score × 10 + 2.0 × Speed_Profile_Score - 0.3 × CoT_penalty
- **G=8 rollouts, K=5 denoising steps, γ=0.6 discount**
- **Speed_Profile_Score = exp(-MAE(v_pred, v_GT))** — novel

## Evaluation Metrics

### Standard metrics (matching prior work for fair comparison):
- **L2 (m)**: average Euclidean displacement at 1s/2s/3s/4s horizons
- **Collision rate (%)**: BEV occupancy overlap at 1s/2s/3s
- **PDMS**: NAVSIM closed-loop PDM score (higher = better)

### Novel KineDrive-specific metrics:
- **SPE (Speed Profile Error)**: mean |v_pred - v_GT| in m/s over 8 steps
  - Measures accuracy of speed prediction (unique to 4D output)
- **HE (Heading Error)**: mean |θ_pred - θ_GT| in degrees
  - Prior work computes only positional L2; we add heading accuracy
- **Kinematic Consistency Rate (KCR)**: % of waypoints with |Δv/Δt| ≤ 5 m/s²
  - Measures physical plausibility of predicted trajectories

## Design Rationale

### Why 4D instead of 2D/3D?

Prior work encodes speed implicitly through positional spacing between waypoints at fixed 0.5s intervals. While this works for smooth motion, it has key limitations:

1. **Controller compatibility**: MPC and PID controllers need explicit speed references to compute control inputs. With only (x,y), the controller must estimate speed from position derivatives, introducing noise.

2. **Safety**: A stationary vehicle at x_t = x_{t-1} = x_{t+2} could mean "stopped at red light" or "error/freeze". Explicit v=0 m/s makes the intent unambiguous.

3. **Language grounding**: "Decelerate to 5 m/s before the turn" is a natural language description that maps directly to the v dimension. This enables better CoT-trajectory coherence.

4. **Evaluability**: Speed Profile Error (SPE) is a new evaluation dimension that captures trajectory quality beyond positional accuracy alone.

### Why Flow Matching over DDPM?

- Fewer denoising steps (10 vs 100): ~10× faster inference
- More stable training gradients (linear flow vs cosine schedule)
- UniDriveVLA achieved 0.51 avg L2 with flow matching vs ReCogDrive's 90.8 PDMS with DDPM
- For 4D space, stable training is more important (extra speed dimension is harder to normalize)

### Why not MoT (Mixture-of-Transformers)?

UniDriveVLA's MoT requires 3 separate transformer stacks (Understanding/Perception/Action) with masked joint attention — extremely memory-intensive for a 3B backbone. KineDrive achieves the separation of concerns via:
- VLM backbone handles scene understanding (via frozen or LoRA weights)
- Separate DiT action head handles trajectory generation (conditioned on VLM context)
- This gives comparable separation at 1/3 the memory cost

## Novelty Summary for Publication

KineDrive's primary contribution is positioning **speed as a first-class planning output** in end-to-end VLMs. This is achieved through:

1. A new 4D action space (x,y,θ,v) backed by a rigorous normalization scheme and kinematic constraint loss
2. CAN bus speed supervision that matches physical reality rather than implicit positional speed
3. K-GRPO reward with explicit speed profile score that incentivizes accurate velocity prediction
4. New evaluation metrics (SPE, HE, KCR) that measure trajectory quality dimensions invisible to prior benchmarks

This makes KineDrive's trajectory predictions directly usable by downstream controllers (MPC, PID, LQR) without any additional speed estimation step — a practically significant improvement for deployment-ready autonomous driving systems.
